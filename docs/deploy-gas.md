# 部署：GitHub Pages 網頁 + Google Apps Script 後台

系統分成兩部分（與 CarTracker 相同的做法）：

| | 放在哪裡 | 更新方式 |
|---|---|---|
| **網頁**（畫面、點名操作） | GitHub Pages，例如 `https://jim0954.github.io/AttendPoint/` | 推送到 `main` 後自動更新（GitHub Actions「發布網頁」） |
| **後台**（讀寫資料、權限檢查） | Google Apps Script，資料存在部署者的 Google 試算表 | 後台程式改變時，擁有者用 `clasp push` 更新並發布新版本 |

網頁會檢查後台版本：後台需要更新時，畫面上方會顯示「⚠️ 後台程式需要更新」，平常不用特別記。

先在電腦上產生部署檔（需要 Node.js 18 以上）：

```bash
npm run build
```

會產生 `dist/gas/`（要放進 Apps Script 的後台程式）與 `dist/web/`（GitHub Pages 的網頁，由 GitHub 自動建置，不用手動處理）。

## 0. 先決定用哪個 Google 帳號部署

程式在 Google 的雲端主機上執行，部署者的電腦不用開著。但部署時「執行身分」選「我」，所以：

- 每個人點名時，Google 都當成是**部署者的帳號**在讀寫試算表。
- 學員名冊、積分、備份都存在**部署者的 Google 雲端硬碟**。
- Apps Script 的每日用量也算在部署者的帳號上。
- 服務人員不需要 Google 帳號，用系統裡的壇務帳號加 PIN 登入；訪客不用登入。
- 網頁本身放在 GitHub Pages，跟 Google 帳號無關。

**正式使用建議另外申請一個佛堂公用的 Google 帳號**來部署，個人資料和佛堂資料分開，以後換人管理時把帳號交接出去就好。

也可以先用自己的帳號在一個班試行，之後再轉到公用帳號、開放給其他班，步驟見「[8. 試行後轉移到公用帳號](#8-試行後轉移到公用帳號)」。

## 1. 建立試算表與 Apps Script 專案

1. 到 Google 雲端硬碟建立一個新的試算表，例如「佛堂點名加分系統」。
2. 在試算表選單點「擴充功能 → Apps Script」。

## 2. 放入後台程式

**方法 A：使用 clasp（建議，之後更新只要一行指令）**

第一次使用 clasp，要先到 [Apps Script 設定](https://script.google.com/home/usersettings) 開啟「Google Apps Script API」（同一個 Google 帳號只要開一次；用過 CarTracker 的話已經開好了）。

```bash
npm install -g @google/clasp
```

```bash
clasp login
```

把 `.clasp.json.example` 複製成 `.clasp.json`，填入專案 ID（Apps Script 編輯器 → 專案設定 → 指令碼 ID），然後：

```bash
npm run build
```

```bash
clasp push
```

（`.clasp.json` 已設定推送 `dist/gas/`，並指定載入順序。`.clasp.json` 不會上傳到 GitHub。）

**方法 B：手動複製（不需安裝任何東西）**

在 Apps Script 編輯器中，依照下面的順序新增指令碼檔案，再把 `dist/gas/` 裡對應檔案的內容貼上：

| 順序 | 檔名 | 來源 |
|---|---|---|
| 1 | `store` | `dist/gas/store.js` |
| 2 | `auth` | `dist/gas/auth.js` |
| 3 | `migrate-v2` | `dist/gas/migrate-v2.js` |
| 4 | `Code` | `dist/gas/Code.js`（取代預設的 Code.gs 內容） |

順序很重要：前三個要排在 `Code` 上面。請貼 `dist/gas/` 裡的檔案，不要貼 `src/` 的原始檔（`Code.js` 的後台版本要建置後才會填上）。

## 3. 設定指令碼屬性

Apps Script 編輯器 → 左側「專案設定」（齒輪）→ 最下方「指令碼屬性」→ 新增：

| 屬性 | 值 | 說明 |
|---|---|---|
| `OWNER_PIN` | 例如 `246810` | 擁有者主帳號 PIN，6–8 位數字，**必填**（建議 8 位；少於 6 位無法登入） |
| `OWNER_NAME` | 例如 `堂主` | 選填，登入畫面顯示的名稱 |
| `BACKUP_KEEP` | 例如 `10` | 選填，自動保留的備份份數，預設 10 |

**請勿把真實 PIN 寫進程式碼或 commit 到 GitHub。**

## 4. 部署後台

1. 編輯器右上角「部署 → 新增部署作業」，類型選「網頁應用程式」。
2. 執行身分：**我**；誰可以存取：**所有人**。
   - 一定要選「所有人」：網頁是從 GitHub Pages 連過來的，不是「所有人」時 Google 會要求登入，網頁就讀不到資料（畫面會提示「請擁有者確認 Apps Script 部署的存取權為『所有人』」）。
   - 選「所有人」不代表誰都能改資料：沒有登入壇務帳號只能看到遮蔽名字的資料，修改一律由後台檢查權限。
3. 第一次部署會要求授權：選你的帳號；出現「Google 尚未驗證這個應用程式」時，按「進階 → 前往（專案名稱）（不安全）」→「允許」。程式是你自己部署的，所以這是正常的。
4. 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。用瀏覽器打開會看到「AttendPoint 後台運作中」，代表後台正常。

## 5. 開啟 GitHub Pages 網頁

1. **開啟 Pages**（只要做一次）：GitHub 上的 AttendPoint →「Settings → Pages」→ Source 選「**GitHub Actions**」。
2. **填入後台網址**：在 GitHub 上打開 `src/config.js` → 按鉛筆（編輯）→ 把 `GAS_URL: ''` 改成剛才的網址，例如 `GAS_URL: 'https://script.google.com/macros/s/xxxx/exec'` →「Commit changes」。
3. **等待發布**：到「Actions」分頁，「發布網頁」跑完（約 1–2 分鐘，綠色勾勾）就完成了。
4. **打開網頁**：`https://<GitHub 帳號>.github.io/<repo 名稱>/`，例如 `https://jim0954.github.io/AttendPoint/`。把網址分享在佛堂群組，建議大家加到手機主畫面。
5. 用擁有者登入（PIN 是 `OWNER_PIN`），到「👑 擁有者 → 帳號管理」為每位服務人員建立壇務帳號。
   - 要放佛堂 LOGO 的話：「👑 擁有者 → 🛠️ 系統與備份 → 🖼️ LOGO → 上傳圖片」。圖片會縮成 180×180，存在試算表隱藏的 `_logo` 工作表，**不會放進 GitHub**；標題、瀏覽器分頁與手機主畫面圖示都會使用。
6. 如果之前用過 v2 單機版：在 v2 電腦的瀏覽器中按 F12 → Console 輸入 `copy(localStorage.temple_checkin_annual_v2)`，再到「擁有者 → 系統與備份 → 匯入資料」貼上，會自動轉換。

`GAS_URL` 留空時，網頁會以單機版運作（資料只存在瀏覽器）。

## 6. 之後更新程式

- **網頁**：推送到 `main` 就會自動發布，不用做任何事。
- **後台（建議：自動更新）**：設定一次後，推送到 `main` 時 GitHub Actions 會自動上傳後台、建立新版本，並把現有部署作業指到新版本（網址不變），手機上不用做任何事。只有後台程式真的改變時才建立新版本：先以 Apps Script API 讀現有部署作業的版本指紋比對（Apps Script 每個專案最多 200 個版本）。設定方式見下方「自動更新後台」。
- **後台（手動）**：沒有設定自動更新時，網頁上方出現「⚠️ 後台程式需要更新」（代表資料規則或後台程式有改），在電腦上：

  ```bash
  git pull
  ```

  ```bash
  npm run build
  ```

  ```bash
  clasp push
  ```

  再到 Apps Script「部署 → 管理部署作業」→ 鉛筆（編輯）→ 版本選「**新版本**」→「部署」。後台網址不會變，不用改 `src/config.js`。

  沒有用 clasp 的話，把 `dist/gas/` 的 4 個檔案重新貼上，再發布新版本。

### 自動更新後台（設定一次）

需要一台電腦做一次登入，之後都不用再碰。

1. **開啟 Apps Script API**：到 <https://script.google.com/home/usersettings>，把「Google Apps Script API」打開。
2. **安裝 Node.js**：命令提示字元輸入 `node -v`，沒有版本號就到 <https://nodejs.org> 安裝 LTS 版，裝好後重開命令提示字元。
3. **安裝 clasp 並登入**（用放試算表的那個 Google 帳號，在瀏覽器按「允許」）：

   ```bash
   npm install -g @google/clasp
   ```

   ```bash
   clasp login
   ```

4. **打開授權檔**（Windows；Mac 用 `open -e ~/.clasprc.json`）：

   ```bash
   notepad %USERPROFILE%\.clasprc.json
   ```

   這個檔案等於你的 Google 授權，**不要貼給任何人、不要放進 repo**。clasp 2.x、3.x 產生的格式都可以。
5. **建立 GitHub Secret**：repo 的 Settings → Secrets and variables → Actions → New repository secret，建立三個：

   | Name | 內容 |
   |---|---|
   | `CLASPRC_JSON` | `.clasprc.json` 的全部內容 |
   | `GAS_SCRIPT_ID` | Apps Script 左邊 ⚙️「專案設定」→「指令碼 ID」 |
   | `GAS_DEPLOYMENT_ID` | 「部署 → 管理部署作業」→ 現有部署的「部署作業 ID」（`AKfyc` 開頭） |

6. **試跑一次**：GitHub 的 Actions →「發布網頁」→「Run workflow」。「更新後台（Apps Script）」這一步出現「✓ 後台網址已是新版本」或「後台已是最新版本」就完成了。

注意：
- 自動更新會用 `dist/gas/` 整份取代 Apps Script 專案的檔案（`store`、`auth`、`migrate-v2`、`Code` 與設定檔），在 Apps Script 編輯器裡手動加的其他檔案（例如預設的「程式碼.gs」）會被移除。
- 後台更新失敗時不會發布網頁（避免網頁比後台新）。訊息會說明原因，例如授權過期就在電腦上重新 `clasp login`，再更新 `CLASPRC_JSON`。
- 轉移到公用帳號時（第 8 節），要用公用帳號重新做一次第 1–5 步。

### 從舊版（網頁放在 Apps Script）升級

如果你的 Apps Script 專案裡還有 `Index` 這個 HTML 檔，那是舊版放網頁用的：照上面「後台」的步驟更新 4 個指令碼並發布新版本後，就可以刪除 `Index`。原本的部署網址改成後台網址使用（填進 `src/config.js`），大家改用 GitHub Pages 的網址。

## 7. 選用：自動更新報表工作表

試算表中的「學員總表／流水帳／服務人員／課次」是給人看的報表：

- **學員總表**：每位學員的入班日期、分數與出席堂數。
- **流水帳**：每一筆點名、加減分、兌換、校正、撤銷。
- **服務人員**：開始服務日期、護持總堂數與各班護持堂數。
- **課次**：每堂課的學員出席人數／應到人數與出席率、服務人員出席人數／應到人數與出席率，以及出席與缺席名單（最新的在最上面）。應到學員是這個班目前的學員；應到服務人員是支援這個班或跨班支援的服務人員。

更新方式：

- **手動**：在試算表選單點「AttendPoint → 更新報表工作表」。
- **下課後自動更新（建議）**：每堂課「結束時間＋30 分鐘」後自動更新。課次沒有填結束時間、或下課後才補點名或加分時，以這堂課最後一次點名、加分或服務人員點名的時間＋30 分鐘為準（補登後會再更新一次）。設定一次（建議用電腦）：
  1. Apps Script 編輯器左邊的 ⏰「觸發條件」→ 右下角「新增觸發條件」。
  2. 「選擇您要執行的功能」選 `autoRebuildReports`；「選擇應執行的部署作業」選「上端（Head）」。
  3. 「選取活動來源」選「時間驅動」；「選取以時間為準的觸發條件類型」選「分鐘計時器」；間隔選「每 10 分鐘」。
  4. 「錯誤通知設定」可選「每天通知我」。按「儲存」，第一次會要求授權，選帳號 →「進階」→「前往 AttendPoint（不安全）」→「允許」。

  觸發條件每 10 分鐘只做檢查，沒有課次到時間就不會動試算表，所以報表會在下課後 30–40 分鐘內更新。讀過資料後會記下資料版本與下一個到期時間（指令碼屬性 `REPORT_PLAN`），資料沒變、也還沒到期時連資料都不讀，一次檢查不到一秒。不需要時，在「觸發條件」把它刪除即可。

## 8. 試行後轉移到公用帳號

先用個人帳號在一個班試行，確認好用後再轉到公用帳號、開放給其他班。

### 試行期間

- 不要把試算表分享給別人，大家用網頁網址操作就好。
- 每隔一段時間到「擁有者 → 系統與備份 → 下載完整備份（JSON）」下載一份，自己留著。
- 可以順便確認：手機點名要等多久、服務人員操作順不順、加扣分項目與小隊設定是否符合班上習慣。

### 轉移時間點

**在開放給其他班之前轉移**。網頁網址不會變，但大家要重新登入一次；那時只有試行班的服務人員受影響，最單純。

### 轉移步驟

1. **用公用帳號部署新的後台**：照本文件第 1–4 步做一次（建立試算表、放入後台程式、設定 `OWNER_PIN`、部署），拿到新的 `/exec` 網址。這時網頁還連著舊後台。
2. **選沒有上課的時間切換**，避免有人在搬的過程中還在點名。
3. **下載舊後台的資料**：用擁有者登入網頁 →「擁有者 → 系統與備份 → 下載完整備份（JSON）」。
4. **網頁改連新後台**：在 GitHub 編輯 `src/config.js`，把 `GAS_URL` 換成新的 `/exec` 網址並 commit，等 Actions「發布網頁」完成（約 1–2 分鐘）。
5. **匯入資料**：重新整理網頁，用**新後台的** `OWNER_PIN` 登入擁有者 →「擁有者 → 系統與備份 → 匯入資料」，選剛下載的檔案，按「取代目前資料並匯入」。學員、班別、課次、流水帳、禮品都會帶過去。
6. **重新建立壇務帳號**：壇務帳號存在 Script Properties 的 `USERS`（帳號多時分段為 `USERS_2`、`USERS_3`…），不在備份檔裡，請在「擁有者 → 帳號管理」重新建立。
7. **確認資料**：看一下學員人數、幾位學員的分數與出席，與轉移前一致。
8. **通知大家重新登入**：網頁網址不變，服務人員用新的壇務帳號登入即可。
9. **封存舊後台**：在舊帳號的 Apps Script 編輯器「部署 → 管理部署作業」，把舊部署封存。有設定自動更新後台的話，用公用帳號重新設定三個 Secret（第 6 節「自動更新後台」），否則會繼續更新到舊後台。
10. **開放給其他班**：其他班的負責人在「班務管理」新增自己的班別，再建立名冊。

> ⚠️ **順序很重要：先匯入試行班的資料（第 5 步），再讓其他班開始建班（第 10 步）。**
> 「匯入資料」會整份取代新系統裡的資料，如果其他班先輸入了，匯入時會被蓋掉。（匯入前雖然會自動留一份備份工作表，但要救回來很麻煩。）

舊試算表裡的 `_backup_*` 備份工作表不會搬過去，但會留在舊帳號的雲端硬碟裡，需要時還找得到。確認新系統運作正常一段時間後，再決定要不要刪除舊試算表。

## 資料存放在哪裡

- 實際資料：隱藏的 `_data` 與 `_data_2` 工作表（JSON 分段存放，請勿手動修改）。兩個工作表輪流寫入，Script Properties 的 `DATA_SHEET` 記錄目前使用哪一個，另一個是前一版。
- 備份：隱藏的 `_backup_日期時間` 工作表（跨年度結算、匯入資料前自動產生）。每次產生新備份時，只保留最新的 10 份（可用 `BACKUP_KEEP` 調整），較舊的自動刪除；**跨年度結算的備份一律保留**，不會自動刪除，也不計入份數。
- 帳號：Script Properties 的 `USERS`（帳號多時分段為 `USERS_2`…，`USERS_PARTS` 記錄段數；PIN 已雜湊）
- LOGO：隱藏的 `_logo` 工作表（擁有者從網頁上傳）

### 寫入安全

每次操作都先寫到沒在使用的那個工作表，確認寫入完整後才切換 `DATA_SHEET`。寫到一半出錯（逾時、試算表忙碌）時，這次操作不會生效，原本的資料也不受影響，再操作一次即可。

如果網頁顯示「資料讀取失敗，為了保護資料已暫停操作」，表示目前使用中的資料工作表被刪除或內容被改壞。系統不會用空白資料覆蓋，請擁有者：

1. 到試算表確認 `_data`、`_data_2` 是否還在（隱藏的工作表可在左下角「所有工作表」清單中找到）。
2. 如果其中一個被刪除或改壞，把 Script Properties 的 `DATA_SHEET` 改成另一個工作表的名稱，就會改用前一版的資料（最後一次操作會遺失）。
3. 或者用擁有者登入，到「擁有者 → 系統與備份 → 匯入資料」匯入之前下載的備份檔（資料讀不到時仍可以匯入）。

## 部署前先在電腦上試用

- **單機版**：`npm run build` 後用瀏覽器開啟 `dist/AttendPoint.html`，資料存在瀏覽器中。
- **模擬雲端版**：`npm run gas-sim` 產生 `dist/gas-sim.html`，在瀏覽器模擬 Apps Script 環境（擁有者 PIN `246810`，資料只存在記憶體）。需要用本機網頁伺服器開啟，例如 `python -m http.server --directory dist`。
